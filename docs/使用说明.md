# RelayDock 中文使用说明

RelayDock 是本地编码 Agent 的接力工作台。它把 Codex / Cursor 等平台上的任务状态整理成可恢复的 Relay Packet，交给 DeepSeek 等兼容模型继续执行，并把结果记入统一账本。

你可以把它当成：

- **工作台**：在 Studio 里建会话、交接、审批、导出；
- **纯桥接**：真实聊天仍留在 Codex / Cursor，RelayDock 只负责记账本和转发。

---

## 1. 环境要求

- Node.js 20+
- Git（可选，但建议在 Git 仓库工作区使用）
- DeepSeek 或其他 OpenAI Chat Completions 兼容 API Key（可选，真实调用时需要）

本项目无第三方 npm 依赖，克隆后可直接运行。

---

## 2. 启动服务

在 PowerShell 中：

```powershell
cd D:\RelayDock
$env:DEEPSEEK_API_KEY = '<你的密钥>'
$env:RELAYDOCK_TOKEN = 'dev-relaydock-token'
node .\bin\relaydock.js serve --workspace D:\你的项目 --port 4173
```

启动后会得到：

| 入口 | 地址 / 命令 |
| --- | --- |
| Studio 可视化界面 | http://127.0.0.1:4173/ |
| Model Gateway | http://127.0.0.1:4173/v1 |
| MCP 控制面 | `node .\bin\relaydock.js mcp --workspace D:\你的项目` |

说明：

- 默认只监听 `127.0.0.1`
- 数据目录默认是工作区下的 `.relaydock`
- `.env.example` 只是变量清单，**不会自动加载**；请用环境变量，或在 Studio 里填写“本次运行密钥”

自定义数据目录：

```powershell
$env:RELAYDOCK_DATA_DIR = 'D:\RelayDock\state'
node .\bin\relaydock.js serve --workspace D:\你的项目
```

---

## 3. 三种使用方式怎么选

| 方式 | 适合场景 | 真实会话在哪 |
| --- | --- | --- |
| Studio 工作台 | 本机可视化交接、审批、看时间线 | RelayDock |
| Gateway 桥接 | 想继续在 Codex/Cursor 里聊天，只换模型后端 | Codex / Cursor |
| MCP 桥接 | 让 Codex/Cursor 主动写入证据并触发交接 | Codex / Cursor |

---

## 4. Studio 可视化工作流

1. 打开 http://127.0.0.1:4173/
2. 点击顶部 **工作区** 按钮，配置当前可读写的项目目录（文件工具不能越出该目录；可点最近路径快速切换）
3. **从 Codex 接手（推荐）**：左侧点「导入 Codex」，选择本机 `~/.codex/sessions` 里的 rollout；系统会自动抽取用户/助手消息并建会话（跳过环境注入噪音），再创建 Checkpoint
4. 或新建空白会话，手动填写目标、约束、验收标准
5. 左下角配置 DeepSeek（或其它 Provider）并测试连接
6. 需要时再点「创建 Checkpoint」/「预览 Relay Packet」
7. 底部选择「接手模型」，输入下一步指令，点「交给接手模型」
8. 若出现写文件 / 跑命令，在「审批」中批准或拒绝
9. 需要回传时点「导出给 Codex」，把 Markdown 贴回原平台
10. 在 Diff 面板查看未提交改动

CLI 等价：

```powershell
node .\bin\relaydock.js codex:list
node .\bin\relaydock.js codex:import --rollout <SESSION_ID或rollout路径>
```

## 5. 纯桥接：Gateway（推荐）

目标：聊天界面仍在 Codex / Cursor，RelayDock 只做转发和记账。

### 5.1 配置第三方平台

把自定义 OpenAI 兼容模型指到 RelayDock：

- **Base URL**：`http://127.0.0.1:4173/v1`
- **API Key**：启动时设置的 `RELAYDOCK_TOKEN`（或 serve 打印的 Bearer Token）
- **Model**：见下表

| 模型 ID | 行为 |
| --- | --- |
| `deepseek` / `relaydock/deepseek` | 注入 Relay Packet 后转发给 DeepSeek |
| `relaydock/deepseek+raw` | 原样转发消息，仍写入账本 |
| `relaydock/deepseek+agent` | 走 RelayDock 审批型 Agent 循环 |

Gateway 已支持：

- `POST /v1/chat/completions`
- `POST /v1/responses`（Codex 用的 Responses API，含工具调用翻译与 SSE）

#### Codex `config.toml` 示例

```toml
model = "relaydock/deepseek"
model_provider = "relaydock"

[model_providers.relaydock]
name = "RelayDock"
base_url = "http://127.0.0.1:4173/v1"
env_key = "RELAYDOCK_TOKEN"
wire_api = "responses"
```

```powershell
$env:RELAYDOCK_TOKEN = 'dev-relaydock-token'
```

说明：Cursor 的 Override OpenAI Base URL 会经云端访问，无法打到本机 `127.0.0.1`；Cursor 请用 MCP。Codex 在本机直连 Gateway 即可。

### 5.2 可选请求头

| 请求头 | 作用 |
| --- | --- |
| `x-relaydock-session` | 复用已有 RelayDock 会话 ID |
| `x-relaydock-external-key` | 绑定外部会话，如 `codex:thread-01`、`cursor:chat-01` |
| `x-relaydock-origin` | 来源平台：`codex` / `cursor` |
| `x-relaydock-title` | 自动建会话时的标题 |

### 5.3 日常步骤

1. 启动 RelayDock `serve`
2. 在 Codex / Cursor 选择上述自定义模型
3. 在原平台正常对话
4. 需要审计、预览 Packet 或处理 `+agent` 审批时，打开 Studio
5. 任务告一段落时导出结果，贴回原平台（可选）

## 6. 纯桥接：MCP

目标：真实会话在 Codex / Cursor，由 Agent 调用 RelayDock 工具完成交接。

### 6.1 启动 MCP

```powershell
node .\bin\relaydock.js mcp --workspace D:\你的项目
```

注意：MCP 使用标准输入输出通信，不要往 stdout 打日志。

### 6.2 Cursor 配置示例

写入 Cursor 的 MCP 配置（路径按本机修改）：

```json
{
  "mcpServers": {
    "relaydock": {
      "command": "node",
      "args": [
        "D:/RelayDock/bin/relaydock.js",
        "mcp",
        "--workspace",
        "D:/YourRepo"
      ]
    }
  }
}
```

### 6.3 推荐工具顺序

1. `relaydock_session_create`  
   带上 `originProvider`（`codex` / `cursor`）和稳定的 `externalKey`
2. `relaydock_message_record`  
   只记录继续任务所需的关键证据；`messageId` 保持稳定，避免重复导入
3. `relaydock_checkpoint_create`  
   保存可恢复工作区状态
4. `relaydock_packet_compile`  
   检查将发送给接手模型的上下文
5. `relaydock_turn_run`  
   或改走 Gateway 继续在原平台聊天
6. 若有写操作：`relaydock_approval_list` → `relaydock_approval_resolve`
7. `relaydock_export`  
   导出 Markdown / JSON，贴回 Codex / Cursor

## 7. CLI 工作流

把 `SESSION_ID` 换成实际会话 ID：

```powershell
# 1. 建立任务契约
node .\bin\relaydock.js session:create --title "完成登录模块" --goal "实现并验证登录流程"

# 2. 从 Codex / Cursor 导入关键对话
node .\bin\relaydock.js message --session SESSION_ID --role user --provider codex --message-id codex:msg-001 --content "用户提出了登录需求"
node .\bin\relaydock.js message --session SESSION_ID --role assistant --provider codex --message-id codex:msg-002 --content "当前实现进度和未完成项"

# 3. 创建 Checkpoint
node .\bin\relaydock.js checkpoint --session SESSION_ID --summary "核心代码已完成，等待联调" --test-status "旧测试未通过"

# 4. 预览 Relay Packet
node .\bin\relaydock.js packet --session SESSION_ID

# 5. 交给接手模型
node .\bin\relaydock.js turn --session SESSION_ID --provider deepseek --instruction "继续完成测试并修复失败项"

# 6. 审批写操作
node .\bin\relaydock.js approval:list --session SESSION_ID
node .\bin\relaydock.js approval:resolve --approval APPROVAL_ID --decision approve --continue

# 7. 导出结果
node .\bin\relaydock.js export --session SESSION_ID --format markdown
```

其它常用命令：

```powershell
node .\bin\relaydock.js status
node .\bin\relaydock.js session:list
node .\bin\relaydock.js provider:list
node .\bin\relaydock.js help
```

## 8. 作为 Codex Skill

把本仓库链接或复制到 Codex skills 目录，例如：

`%USERPROFILE%\.codex\skills\relaydock`

然后在 Codex 中按 `SKILL.md` 执行交接：记录目标 → Checkpoint → Packet → turn / Gateway → 导出回传。

Skill **不会**自动读取 Codex 私有历史，也不会静默改掉 Codex 的全局模型配置。

---

## 9. 数据与安全

- 默认本机回环访问；Gateway Token 视同本地密钥
- 账本为追加写 JSONL；大快照放在 `blobs/`
- API Key 只来自环境变量或进程内存，不写入账本
- 外部模型消息标记为 `untrusted`
- 写文件、跑命令默认需要人工审批
- 命令不走 shell，并限制工作目录、超时和输出大小
- 默认排除 `.env`、密钥、私钥等敏感路径

## 10. 常见问题

**Q：Studio / Gateway 连不上？**  
先访问 http://127.0.0.1:4173/api/health 。若端口占用，换 `--port`，或确认已有实例在跑。

**Q：没有 API Key 能做什么？**  
可以建会话、记消息、做 Checkpoint、预览 Packet；不要发起真实模型请求。

**Q：Codex / Cursor 的原会话能直接打开吗？**  
不能。RelayDock 会话是自己的账本；需通过 Gateway 自动捕获，或 MCP / CLI 显式导入。

**Q：Gateway 和 Studio 要一起开吗？**  
`serve` 同时提供两者。纯桥接时可以不打开 Studio，但审批、预览 Packet 时 Studio 更方便。

**Q：`+agent` 和普通模型有什么区别？**  
普通 / `+raw`：转发聊天，工具循环仍在原平台。  
`+agent`：由 RelayDock 跑带工具的 Agent 循环，写操作要先审批。
